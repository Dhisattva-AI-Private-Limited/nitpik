# NitPik Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build NitPik Phase 1 — a zero-dependency JS library (<15KB gzip) that turns any HTML page into a reviewable document with per-element commenting, plus a marketing site, MCP server, and Claude Code skill.

**Architecture:** Single IIFE bundle built with esbuild from ES6 source modules. All UI lives inside a Shadow DOM attached to `<body>`. Six source modules (events, path, discovery, storage, styles, ui) are orchestrated by an index module that exposes the `window.NitPik` global. The MCP server is a separate Node.js package in `mcp/` that manipulates HTML files.

**Tech Stack:** Vanilla JS (ES6 source → ES5 IIFE output), esbuild, vitest (happy-dom environment for DOM tests), Playwright for e2e.

**Spec:** `docs/superpowers/specs/2026-11-07-nitpik-design.md`

## Global Constraints

- Bundle target: `dist/nitpik.min.js` < 15KB gzipped (target, not hard gate)
- Zero runtime dependencies
- Shadow DOM encapsulation — all NitPik UI inside one Shadow DOM on `<body>`
- Must work on `file://` protocol — `document.execCommand('copy')` fallback for clipboard
- ES5 syntax output; modern APIs (IntersectionObserver, ShadowRoot, MutationObserver) used directly
- Identifiers: `window.NitPik` global, `data-nitpik-*` attributes, `window.nitpikOnComment` callback
- Comment schema version: `"1"` — fields: selector, path, tagName, textPreview, comment, reviewer, timestamp
- Marketing site: self-contained HTML, everything inlined, light theme, Animotion MCP icons only
- Max ~200 triggers per page; innermost commentable element wins on nesting
- Keyboard: Tab through triggers, Enter to open, Escape to close (Phase 1)

## Review Focus

1. **Clipboard fails on `file://`:** `navigator.clipboard.writeText` requires secure context. User expects copy to work. Must fall back to `document.execCommand('copy')` with a hidden textarea — test this path explicitly in e2e.
2. **Host page with `NitPik` global already defined:** Double-load or naming collision. Library should warn and bail rather than corrupt state.
3. **Element repositioning after discovery:** Lazy images, accordion open/close, resize — trigger overlay drifts from its element. A ResizeObserver or periodic reposition is expected.
4. **Popover label overflow:** 200-char element path in a 300px popover. Label must truncate with ellipsis at ~80 chars.
5. **Page with 500+ commentable elements:** Must cap at 200 and not freeze the page. Discovery must short-circuit, not silently process all 500.

- [ ] **Step 3: Implement `src/discovery.js`**

`discoverElements`: Query using a combined selector for headings, images/video/svg[width>24]/iframe, `[class*="card"],[class*="tile"],[class*="item"],[class*="feature"],[class*="tier"],[class*="step"],[class*="hero"],[class*="cta"]`, buttons, `a` with text, plus `[data-nitpik]`. Filter out elements matching `exclude` selector or carrying `data-nitpik-ignore`. Filter `[class*="item"]` to only match elements with substantial content (>50 chars or >80px tall) to avoid noise. Deduplicate nested: if both parent and child match, keep only child (innermost wins). Cap at `maxElements`. For each, build `ElementInfo` using path.js functions. Use `IntersectionObserver` to track which elements are in the viewport — triggers are only attached to visible elements and dynamically added/removed as elements scroll in/out.

`observeDOM`: Attach a `MutationObserver` on `root` for `childList` + `subtree`. On mutation, collect added nodes, run them through the same selector matching, call `callback` with the new `ElementInfo[]`. Return a function that disconnects the observer.

`createVisibilityObserver(onVisible, onHidden) → () => void`: Wraps IntersectionObserver. Observes all discovered elements. Calls `onVisible(element)` when an element enters the viewport, `onHidden(element)` when it leaves. Returns teardown function. This is consumed by index.js to lazily attach/detach triggers — triggers only exist for elements currently on screen, keeping DOM weight low on long pages.
